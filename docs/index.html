Bird Watch: When Can You See 'Em?

Predicting the time of day a bird can be sighted from where, when, and how long birders looked, comparing k-Nearest Neighbors, Naive Bayes, and CART decision trees on eBird observations.

Problem Statement & Motivation

Problem statement

Birds keep schedules. Some species are most active at first light; others are easier to find in the afternoon or after dusk. Given a species, a location, a date, and how long an observer spent looking, we want to predict which part of the day that bird is likely to be seen.

We frame this as a four-class classification problem and compare three classic machine-learning methods, each implemented from scratch: k-Nearest Neighbors, Naive Bayes, and a CART decision tree.

Why are we doing this?

This study started out as genuine curiosity in finding patterns to birds' behavior, and a realization that eBird, a community of birdwatchers, provide exactly the needed data for it.

Knowing when a bird might appear has practical applications: it can help birdwatchers schedule their outings, researchers schedule surveys for more efficient excursions, which can be applied to conservations efforts especially within the area we scoped the dataset in (Laguna, Los Baños, Mt. Makiling)

Preprocessing

  1. Column selection. Only species, latitude, longitude, observation date, start time and duration are kept. Scientific name, count, locality and distance are dropped.
  2. Missing values. Rows with no start time or no duration are removed.
  3. Date parsing. The observation date is split into month and day. The year is dropped so the models learn seasonal patterns, not specific years.
  4. Labeling. The start hour is mapped to one of the four classes above.
  5. Shuffling. Rows are shuffled with a fixed seed (67) so the split is not ordered by date and results are reproducible.
  6. Model-specific encoding. Each model then transforms the features differently (scaling, binning or raw values), as described in Methods.

Methods

All three classifiers are written from scratch in Python using only the standard library. Shared loading, splitting and scaling code lives in src/utils.py.

Instance-based

k-Nearest Neighbors

How it works

A non-parametric, lazy learner that stores the dataset without immediate training, classifying new inputs by proximity and majority voting (GeeksforGeeks, 2026).

  1. Select K: Sets the number of nearest neighbors to inspect.
  2. Calculate Distance: Computes proximity (Euclidean, Manhattan, or Minkowski) between the target and all stored training points.
  3. Find Nearest Neighbors: Identifies the k data points with the smallest distances.
  4. Majority Voting: Assigns the class label most frequent among the k neighbors.
Our implementation src/knn.py
  1. Encode & Scale: Coordinates and duration are min-max scaled to [0, 1]. Date is converted to day-of-year fraction (day_of_year / 366).
  2. Minkowski with Wrap: Computes distance across all 4,801 training rows with p = 2. Categorical species incurs 0/1 penalty; date uses circular wrapping min(|x-y|, 1-|x-y|) so Dec 31 & Jan 1 are adjacent.
  3. Sort & Slice: Ranks all distances ascending and extracts the top k = 10 nearest neighbors.
  4. Plurality Vote: Tallies label counts among the 10 neighbors; returns the majority time category.
Probabilistic

Naive Bayes

How it works

A probabilistic classifier based on Bayes' Theorem under the “naive” assumption of feature independence that each feature contributes without affecting others (GeeksforGeeks, 2026).

  1. The Naive Assumption: Assumes features are conditionally independent given the class: P(X|y) = ∏ P(xi|y).
  2. Bayes' Theorem: Combines class prior probabilities P(y) and likelihoods: P(y|X) ∝ P(y) ∏ P(xi|y).
  3. Decision Rule: Chooses the class with the highest posterior probability: ŷ = argmax P(y|X).
Our implementation src/naive_bayes.py
  1. Quantile Discretization: Species is kept as raw categorical values. Continuous coordinates and duration are partitioned into 4 equal-frequency quartiles using training cutoffs; date is binned into 4 seasons.
  2. "Bag of Birds" Matrix: Scans training rows into nested count dictionaries bob[class][feature][bin] alongside class prior tallies.
  3. Smoothed Likelihoods: For a test sighting, calculates feature likelihoods using Laplace smoothing (count + 1) / (total + 1 × V) to eliminate zero counts.
  4. Normalized MAP Decision: Multiplies likelihoods by class priors, normalizes across all 4 target time classes, and returns the highest-probability class.
Tree-based

Decision Tree (CART)

How it works

A recursive algorithm that constructs a binary decision tree by finding the feature and threshold that produce the highest reduction in impurity at each step (GeeksforGeeks, 2025).

  1. Evaluate Best Split: Tests features and candidate threshold values using Gini Impurity (1 − ∑ pi2).
  2. Create Binary Child Nodes: Splits the data into two child nodes (left ≤ threshold, right > threshold) based on the optimal split.
  3. Recursive Splitting: Repeats recursively until reaching stopping criteria (such as maximum depth or minimum sample size).
Our implementation src/decision_tree.py
  1. Exhaustive Split Evaluation: Tests every unique value of all features as candidate binary cuts (== for species, < for numeric features).
  2. Weighted Gini Selection: Calculates sample-weighted Gini impurity across candidate left/right groups; selects the threshold with minimum Gini.
  3. Recursive Tree Construction: Recursively splits child nodes until reaching max_depth = 5, min_size = 10, or a pure node, forming leaf majority labels.
  4. Binary Rule Traversal: Traverses the resulting nested Python dictionary tree from root to leaf following threshold tests to return the predicted class.

Experimental Setup

Data split

Sightings from the same checklist share the same location, date and duration. We group rows by these values and assign whole groups to either training or test (utils.splitter), so one birding outing never appears on both sides. Groups are added to training until it reaches about 4,800 rows; the rest form the test set.

Evaluation metrics

Because the classes are imbalanced, we report several metrics side by side.

Accuracy

correct ÷ total

Overall hit rate. Easy to read, but it rewards always guessing the most common class.

Precision

TP ÷ (TP + FP)

Of the sightings predicted as a class, how many really were that class.

Recall

TP ÷ (TP + FN)

Of the sightings that truly belong to a class, how many the model found.

F1-score

2PR ÷ (P + R)

Balances precision and recall. Macro averages classes equally; weighted weights them by size.

Confusion matrix

actual × predicted

Shows exactly which classes get mixed up with which.

Baseline

A model that always answers "Early Morning" scores 43.1% accuracy on the test set (517 of 1,199) but only 15.1% macro F1, since it never finds the other three classes. We use it as the floor every method must beat.

Discussion

Why the methods performed as they did

k-NN

e.g. effect of distance on mixed features, neighbors dominated by the majority class, sensitivity to k and p.

Naive Bayes

e.g. whether the independence assumption holds, what binning gains or loses, role of the class prior.

Decision Tree

e.g. which features it split on first, what depth 5 can and cannot capture, which classes its leaves never predict.

Influence of the evaluation metrics

How the winner changes between accuracy and macro F1, and what that says about each method's bias toward Early Morning. Refer to Tables 1–3 and Figure 3.

Limitations

  • The dataset does not fully suit the study's goal. eBird keeps track of when birdwatchers see the birds, which doesn't necessarily equate to when birds are actually active.
  • Data set is heavily imabalnced. Early Morning sightings make up 50.3% of the data, while Night sightings make up only 5.8%
  • e.g. a single train/test split; results may vary with a different seed.

Possible improvements

  • Usa data that records bird activity directly: camera traps, automated recorders that are up 24/7.
  • Add more features, weather conditions (temperature, rainfall), other factors that can affect bird activity.
  • e.g. new features such as weather, habitat, or effort distance.
